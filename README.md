# XML → JSONL Portfolio Recreation

A portfolio recreation inspired by a banking reporting-data solution: large XML reporting files are turned into report-ready JSONL using Excel reference mappings, business rules and validation.

> This is **not** the original client application and uses **no client data**. Everything in `demo/` is fictional, and the FormulierID rule sets are representative, not the original rules.

## What's here

| Folder | What it is |
|---|---|
| `frontend/` | The portfolio page: React + Vite, one continuous scroll, one interaction (*Run example transformation*). |
| `processor/` | The real transformation logic in Python (pandas for the Excel hierarchy). Source of truth for behaviour. |
| `demo/` | Fictional XML, Excel hierarchy workbook, mapping/rule config and expected JSONL. |
| `workbench/` | An earlier interactive converter (upload your own XML, inspect warnings). Kept as a secondary tool; not part of the portfolio story. |

The page does not call a backend. It reads `frontend/src/data/snapshot.json`, which is **generated by the Python processor** from the demo files, and a test fails if the checked-in snapshot ever differs from what the processor produces.

## Run it

Python processor (Python 3.9+):

```bash
python3 -m venv .venv
.venv/bin/pip install -r processor/requirements.txt
.venv/bin/python -m processor.cli demo/DEMO_CB77.xml          # JSONL to stdout, warnings to stderr
.venv/bin/python -m processor.cli demo/DEMO_CB77.xml demo/DEMO_MB0100.xml --out-dir out
.venv/bin/python -m processor.generate_snapshot               # refresh frontend/src/data/snapshot.json
npm run test:py                                               # 25 tests
```

Frontend (Node 20+):

```bash
cd frontend
npm install
npm run dev        # http://localhost:5173
npm test           # UI tests, including the signature interaction
npm run build      # static site in frontend/dist (relative paths, host anywhere)
```

Workbench: `npm start` at the repo root, then open http://localhost:8080. `npm test` runs its tests.

## Behaviour implemented (processor)

Reads the `<rapportage>` metadata and every `<post>`; resolves `EBA_<Domain>_<Member>` values through the latest dated Excel hierarchy entry (case-sensitive; the original code is kept and a warning raised when there is no mapping); normalises numbers and `TRUE`/`FALSE`; applies representative FormulierID rules; detects exact duplicates (same value + row + column), keeps the first and continues; keeps `rijnr` as grouping information only; writes deterministic compact JSONL. Malformed XML raises a clear, located error. Output is compared byte-for-byte with `demo/expected_*.jsonl`.

## Representative vs. recalled

Recalled from the original work: the problem, scale (60K–70K records per file, ~25 datasets), the generic-plus-report-specific transformation approach, the Excel hierarchy lookup, duplicate handling and the correct-and-reprocess loop. The 20–25 days → ~1 day per file figures are project-reported, not a benchmark.
Representative (invented for this demo): all data values, FormulierIDs, the `report_code` field and the `DEMO_REL_01` value mapping.
