    The problem
    
        
    Bank reports (monthly, quarterly, annual) start as raw XML files with 60,000–70,000 <post> records each. Business users had to turn them into exactly the structure and values the reporting platform expected, across about 25 different reports, each with its own FormulierID. Preparing one took roughly 20–25 days by hand. With the Python automation it took about one day per correct file recollection, not measured.
    
      
    

      
    
        
    The pipeline
    
        
      
          
    1. Parse the XML. Malformed XML stops the run; nothing is produced.
      2. 
          
    2. Read metadata. FormulierID, period, version, frequency from <rapportage>.
      3. 
          
    3. Extract every <post>. Value, row (rij), column (kolom), rijnr.
      4. 
          
    4. Resolve coded values. EBA_FIN_X01 → Domain FIN + Member X01 → look up Structure in the Hierarchies sheet (latest date wins). No match: keep the code, so the gap is visible.
      5. 
          
    5. Normalise types. "42.00" becomes 42, "0.93" becomes 0.93, text stays text.
      6. 
          
    6. Apply FormulierID rules. Only for reports that need them: FALSE → false, internal business codes.
      7. 
          
    7. Detect duplicates. Highlight with line numbers; keep going so users see every problem in one pass.
      8. 
          
    8. Keep related posts together with rijnr. Posts sharing a number belong to one logical group. It is preserved for grouping and never used in calculations.
      9. 
          
    9. Write JSONL. One JSON object per line, ready to upload.
      10.
